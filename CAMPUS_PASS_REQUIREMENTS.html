📋 Project Overview

What is Campus Pass?

Campus Pass is a comprehensive digital outpass management system designed for educational institutions (colleges, universities, hostels) to streamline the process of students requesting, wardens approving, and security personnel verifying outpasses for leaving campus premises.

Key Objectives

🎯 Digitize Manual Process

Replace paper-based outpass system with a digital, trackable solution

⚡ Real-time Updates

Instant notifications for all stakeholders using WebSocket technology

🔒 Secure & Verifiable

QR code-based verification to prevent fraud and ensure authenticity

📊 Analytics & Tracking

Complete audit trail and analytics for administrators

📱 Mobile-First Design

Responsive interface accessible from any device

🔐 Role-Based Access

Different interfaces and permissions for each user type

❗ Problem Statement

Current Challenges in Traditional Outpass Systems

1. Manual Paper-Based Process

  • Students fill physical forms
  • Forms get lost or damaged
  • No digital record or backup
  • Difficult to track and audit

2. Delayed Approvals

  • Students wait hours/days for warden approval
  • No notification system
  • Wardens may miss urgent requests
  • No priority handling for emergencies

3. Security Concerns

  • Easy to forge paper outpasses
  • No way to verify authenticity at gate
  • Students may leave without proper authorization
  • Difficult to track who is currently outside campus

4. Lack of Accountability

  • No record of check-in/check-out times
  • Cannot track overdue students
  • No emergency contact information readily available
  • Parents/guardians not informed

5. Administrative Burden

  • Manual record-keeping is time-consuming
  • Difficult to generate reports
  • No analytics on outpass patterns
  • Hard to identify frequent violators

✅ Our Solution

Campus Pass Digital Platform

A comprehensive web-based application that digitizes the entire outpass lifecycle from request to return, with role-based access for students, wardens, and security personnel.

Core Features

  • Digital Request System: Students submit outpass requests online with all required details
  • Instant Notifications: Real-time alerts via WebSocket for all status changes
  • QR Code Verification: Unique QR codes for each approved outpass
  • Mobile QR Scanner: Security can scan QR codes using phone camera
  • Automated Emails: Email notifications with PDF attachments
  • Dashboard Analytics: Real-time statistics and insights
  • Audit Trail: Complete history of all actions
  • Overdue Tracking: Automatic detection of students who haven't returned

👥 Roles & Permissions

👨‍🎓 Student (Role: 0)

Primary Users: College/University students living in hostels

Permissions:

  • ✅ Create new outpass requests
  • ✅ View own outpass history
  • ✅ View outpass details (status, QR code, dates)
  • ✅ Cancel pending outpass requests
  • ✅ Update profile information
  • ✅ Download approved outpass PDF
  • ✅ Receive real-time notifications
  • ❌ Cannot approve/reject outpasses
  • ❌ Cannot view other students' outpasses
  • ❌ Cannot perform check-in/check-out

Use Cases:

  • Going home for weekend/holidays
  • Medical emergencies
  • Family functions/events
  • Job interviews
  • Personal errands in city

👨‍🏫 Warden (Role: 2)

Primary Users: Hostel wardens, hostel superintendents

Permissions:

  • ✅ View all outpass requests for their hostel
  • ✅ Approve outpass requests (generates QR code)
  • ✅ Reject outpass requests with reason
  • ✅ View student details and history
  • ✅ View analytics and reports
  • ✅ Receive notifications for new requests
  • ✅ Filter outpasses by status, date, student
  • ✅ View overdue students list
  • ✅ Update own profile
  • ❌ Cannot create outpass requests
  • ❌ Cannot perform check-in/check-out
  • ❌ Cannot view outpasses from other hostels

Responsibilities:

  • Review outpass requests promptly
  • Verify student information and reason
  • Approve/reject based on hostel rules
  • Monitor overdue students
  • Maintain discipline and safety

👮 Security Officer (Role: 3)

Primary Users: Campus security guards, gate security personnel

Permissions:

  • ✅ Scan QR codes using mobile camera
  • ✅ Verify outpass authenticity
  • ✅ Perform check-out (student leaving campus)
  • ✅ Perform check-in (student returning to campus)
  • ✅ View currently checked-out students
  • ✅ View check-in/check-out history
  • ✅ View overdue students
  • ✅ Update own profile
  • ❌ Cannot create outpass requests
  • ❌ Cannot approve/reject outpasses
  • ❌ Cannot modify outpass details

Responsibilities:

  • Verify QR code before allowing exit
  • Record accurate check-out time
  • Verify student identity matches outpass
  • Record check-in time when student returns
  • Report suspicious activities
  • Ensure only authorized students leave campus

👨‍💼 Admin (Role: 1)

Primary Users: System administrators, college management

Permissions:

  • ✅ Full system access
  • ✅ Create/manage users (students, wardens, security)
  • ✅ View all outpasses across all hostels
  • ✅ Generate system-wide reports
  • ✅ Configure system settings

  • ✅ Override outpass decisions (if needed)

🔄 Complete User Workflows

Workflow 1: Student Creates Outpass

Step 1: Student logs in → Redirected to dashboard
Step 2: Clicks "Create Outpass" → Navigate to form
Step 3: Fills form:
  • Reason for leaving (dropdown: Home, Medical, Personal, etc.)
  • Destination address
  • From date & time
  • To date & time (expected return)
  • Contact number during leave
  • Emergency contact (parent/guardian)
  • Purpose/additional details
Step 4: Form validation (Zod schema)
  • All required fields filled
  • Valid dates (from < to, future dates)
  • Valid phone numbers
  • No overlapping outpasses
Step 5: Submit → API call POST /api/student/outpasses
Step 6: Backend creates outpass with status "PENDING"
Step 7: Backend sends notification to warden (Socket.io)
Step 8: Backend sends confirmation email to student
Step 9: Student sees success message → Redirected to history
Step 10: Student receives real-time notification "Request submitted"

Workflow 2: Warden Approves Outpass

Step 1: Warden receives notification (Socket.io + Email)
Step 2: Warden logs in → Dashboard shows pending count
Step 3: Clicks "Pending Requests" → List of pending outpasses
Step 4: Clicks on outpass → View full details:
  • Student name, roll number, department, year
  • Hostel, room number
  • Reason, destination, dates
  • Contact numbers
  • Student's outpass history
Step 5: Warden reviews and decides:
  • Option A: Approve → Add remarks (optional) → Click "Approve"
  • Option B: Reject → Add reason (required) → Click "Reject"
Step 6 (If Approved): API call PATCH /api/warden/outpass/:id/approve
Step 7: Backend generates unique QR code with outpass data
Step 8: Backend generates PDF with QR code
Step 9: Backend sends email to student with PDF attachment
Step 10: Backend sends real-time notification to student (Socket.io)
Step 11: Outpass status updated to "APPROVED"
Step 12: Student can now download PDF and show QR at gate

Workflow 3: Security Checks Out Student

Step 1: Student arrives at gate with approved outpass (QR code)
Step 2: Security officer opens /security/scan-qr
Step 3: Camera activates (html5-qrcode library)
Step 4: Student shows QR code (from phone or printed PDF)
Step 5: QR code scanned → Data decoded
Step 6: Frontend extracts outpass ID from QR data
Step 7: API call POST /api/security/check-out
  • Body: { outpassId, guardName, remarks }
Step 8: Backend verifies:
  • Outpass exists and is approved
  • Not already checked out
  • Current date is within outpass dates
  • QR code is valid (not expired)
Step 9: Backend updates outpass:
  • Status → "CHECKED_OUT"
  • checkOutTime → current timestamp
  • checkOutBy → security officer ID
Step 10: Backend sends notification to student (Socket.io)
Step 11: Success message shown to security officer
Step 12: Student can now leave campus

Workflow 4: Security Checks In Student

Step 1: Student returns to campus
Step 2: Security officer opens /security/scan-qr
Step 3: Student shows QR code or provides outpass number
Step 4: Security scans QR or searches by outpass number
Step 5: API call POST /api/security/check-in
  • Body: { outpassId, guardName, remarks }
Step 6: Backend verifies:
  • Outpass is checked out
  • Not already checked in
Step 7: Backend checks if overdue:
  • If current time > expected return time → Mark as overdue
  • Calculate delay duration
Step 8: Backend updates outpass:
  • Status → "CHECKED_IN" or "OVERDUE"
  • checkInTime → current timestamp
  • checkInBy → security officer ID
Step 9: Backend sends notification to student (Socket.io)
Step 10: If overdue, notify warden
Step 11: Success message shown to security officer
Step 12: Student is back in hostel

Workflow 5: Warden Rejects Outpass

Step 1: Warden reviews pending outpass request
Step 2: Warden finds issue (invalid reason, dates, etc.)
Step 3: Warden clicks "Reject" button
Step 4: Modal opens asking for rejection reason
Step 5: Warden enters reason and confirms
Step 6: API call PUT /api/warden/outpass/:id/reject
  • Body: { reason: "Rejection reason text" }
Step 7: Backend updates outpass:
  • Status → "REJECTED"
  • rejectionReason → provided reason
  • rejectedBy → warden ID
  • rejectedAt → current timestamp
Step 8: Backend sends notification to student (Socket.io + Email)
Step 9: Student receives rejection notification with reason
Step 10: Student can create new outpass with corrections

Workflow 6: Student Cancels Outpass

Step 1: Student has pending/approved outpass
Step 2: Plans change, student needs to cancel
Step 3: Student opens outpass details page
Step 4: Student clicks "Cancel Outpass" button
Step 5: Confirmation dialog appears
Step 6: Student confirms cancellation
Step 7: API call PUT /api/student/outpass/:id/cancel
Step 8: Backend verifies:
  • Outpass belongs to student
  • Status is PENDING or APPROVED (not checked out)
Step 9: Backend updates outpass:
  • Status → "CANCELLED"
  • cancelledAt → current timestamp
Step 10: If was approved, notify warden (Socket.io)
Step 11: Success message shown to student
