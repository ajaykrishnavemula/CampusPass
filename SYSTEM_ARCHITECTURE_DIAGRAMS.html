📐 1. System Architecture

1.1 Layered Architecture (N-Tier)

Key Benefits:

  • Separation of Concerns: Each layer has a specific responsibility
  • Maintainability: Changes in one layer don't affect others
  • Testability: Each layer can be tested independently
  • Scalability: Layers can be scaled independently

1.2 Technology Stack

1.3 Database Schema (MongoDB Collections)

Database Indexing Strategy:

Users: email (unique), role | Outpasses: student, status, createdAt (desc) | Hostels: name (unique) | Notifications: user, isRead, createdAt (desc)

🔄 2. System Workflows

2.1 Outpass Creation & Approval Workflow

Workflow Steps:

  • Step 1: Student fills outpass form (reason, destination, dates)
  • Step 2: Backend validates (system active, user permissions, overdue count)
  • Step 3: Outpass created with status "pending"
  • Step 4: Warden receives real-time notification via WebSocket
  • Step 5: Warden reviews and approves/rejects
  • Step 6: If approved, QR code generated and student notified

2.2 Security Check-in/Check-out Workflow

Check-in/Check-out Process:

  • Check-out: Security scans QR → Validates outpass → Updates status to "checked_out" → Logs action
  • Check-in: Security scans QR → Checks if overdue → Updates status → If overdue, increments count
  • Auto-restriction: If student has 3+ overdue returns, automatically set canCreateOutpass = false
  • Real-time updates: Student receives notification immediately via WebSocket

2.3 Complete Data Flow Diagram

Key Data Flow Patterns:

Request Flow: UI → API Gateway → Middleware (Auth, Validation) → Business Logic → Data Layer → Database
Response Flow: Database → Data Layer → Business Logic → API Gateway → UI
Real-time Flow: Event → Notification Service → WebSocket → Connected Clients
Security: JWT tokens in headers, role-based middleware, rate limiting, CORS, Helmet
